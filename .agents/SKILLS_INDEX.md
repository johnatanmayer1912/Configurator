## Skill Activation Flow

### Standard Activation Flow

```
1. RESYNC (U-RESYNC)
   ↓
2. Governance Framework (G-GOVERNANCE)
   ↓
3. Council Role(s) (based on task context)
   ↓
4. Domain Specialist(s) (if applicable)
   ↓
5. Team Meeting Council (U-COUNCIL) - only if conflicts arise
```

### Task-Based Activation Examples

**Code Implementation:**
```
RESYNC → Governance → System Architect → Lead Developer → 
Security Reviewer → QA Engineer → Observability Engineer → 
Documentation Steward → Release Manager
```

**Documentation Changes:**
```
RESYNC → Governance → Documentation Steward → 
Prompt Librarian (if prompt-related) → Release Manager (if release-related)
```

**Quality Validation:**
```
RESYNC → Governance → QA Engineer → Lead Developer → 
System Architect → Security Reviewer
```

**Security Review:**
```
RESYNC → Governance → Security Reviewer → System Architect → 
Lead Developer → Release Manager
```

**Network Topology Work:**
```
RESYNC → Governance → System Architect → Lead Developer → 
QA Engineer → Network Topology (U-TOPO)
```

## Skill Usage Guidelines

### Automatic Activation
All skills are designed to be **automatically activated** based on task context. The AI assistant will determine which skills are relevant and activate them in the appropriate order without requiring manual user invocation.

### Skill Coordination
Skills are designed to work together collaboratively:
- Each skill knows its required collaborators
- Skills coordinate through defined interfaces
- Conflicts are resolved through escalation to Team Meeting Council
- Dependencies are respected in execution order

### Skill Specialization
Each skill has a defined domain of expertise:
- Council roles cover broad governance and development areas
- Domain specialists provide deep expertise in specific technical domains
- Skills are designed to be complementary and non-overlapping
- Skills can be combined based on task complexity

## Skill Maintenance

### Updating Skills
- Skills should be updated when platform capabilities change
- Skills should reflect current policies and procedures
- Skills should be validated against actual platform behavior
- Skills should be tested for effectiveness and accuracy

### Adding New Skills
- New skills should follow established skill template format
- New skills should have clear activation rules
- New skills should define their coordination requirements
- New skills should be documented in this index

### Skill Deprecation
- Skills should be deprecated when their domain is no longer relevant
- Deprecation should be communicated through governance framework
- Deprecation should preserve historical capability if possible
- Deprecation should include migration guidance
