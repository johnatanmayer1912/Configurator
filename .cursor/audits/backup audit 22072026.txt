## P0 - Critical Issues (Immediate Action Required)

### P0-001: VLANs Not Appearing in Multi-Switch Configuration Output
**Location:** `api/main.py:1387-1404`, `core/renderer.py:134-138`, `templates/nxos_base.j2:136-138`  
**Lens:** Functionality  
**Scope:** Multi-Switch  
**Complexity:** High  
**Evidence:** Backend accepts VLANs from SwitchConfig (api/main.py:325) and applies them to device.vlans (api/main.py:1397). Renderer passes device.vlans to Jinja2 template (renderer.py:134-138). Template iterates over device.vlans (nxos_base.j2:136-138). However, in multi-switch deployments, VLANs may not be propagated to interface configurations (switchport access vlan / switchport trunk allowed vlan).
```python
# api/main.py:1397 - VLANs applied to device
device.vlans = [VLAN(id=v.id, name=v.name) for v in switch_config.vlans]

# renderer.py:134-138 - Device passed to template
rendered = template.render(
    device=device,
    metadata=meta,
    features=self._feature_flags(device),
)

# nxos_base.j2:136-138 - Template iterates VLANs
{% for vlan in device.vlans %}
vlan {{ vlan.id }}
  name {{ vlan.name }}
{% endfor %}
```
**Impact:** User-specified VLANs appear in VLAN section but not in interface configurations. Multi-switch deployments generate configs without proper VLAN assignment to interfaces.
**Needed Outcome:** VLANs specified in multi-switch deployment must appear in both VLAN section AND interface configurations (switchport access vlan / switchport trunk allowed vlan).
**Fix Required:** Ensure scenario engine and interface customizer properly assign VLANs to interfaces in multi-switch deployments. Add validation that interface VLANs match device VLANs.
**Owner Skill:** nst-python-backend
